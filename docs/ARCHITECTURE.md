# 主动ETF Dashboard 上市准备架构

## 目标

一套代码支持三种状态：上市前模拟、Cloudflare真实数据运行、公司内网运行。前端只依赖稳定的 `/api/v2` 契约，不依赖具体数据库。

## 数据链路

1. 原始层：交易所PCF、NAV、IOPV、份额、二级市场行情、合同基准、股票因子和人工Excel。
2. 原始文件层：R2或公司内网对象存储，按来源/日期/版本保存，不覆盖更正前文件。
3. 结构化层：D1（18只产品日频首期）或内网PostgreSQL，保存有效日期、可获得时间、入库时间和质量状态。
4. 计算层：日度调仓、换手、主动份额、风格漂移、资金流、流动性覆盖、持仓重合和收益归因。
5. 发布层：验证通过后生成不可变Dashboard快照；前端不直接拼接未校验的原始表。

## 上市前必须联调的数据任务

| 时点 | 任务 | 失败处理 |
|---|---|---|
| 开市前 | 获取PCF、校验版本与成分权重 | 保留上一有效版本并标红 |
| 盘中 | 更新成交、价差、折溢价和IOPV偏离 | 降级到延迟行情并标注 |
| 收盘后 | NAV、份额、基准和股票行情对齐 | 禁止发布不完整日期 |
| 日终 | 计算调仓、风格、资金流、归因和规则监测 | 旧快照继续服务，记录失败 |
| 发布 | 质量检查通过后写入dashboard_snapshots | 保存模型版本和计算时间 |

## Git与环境边界

Git保存前端、Worker、SQL迁移、计算代码、测试和文档。Git不保存真实持仓文件、行情文件、数据库、API令牌或公司凭证。开发、预生产、生产使用不同D1/R2和密钥。

生产数据库迁移应先在预生产执行和备份，再人工批准应用到生产；不要把数据库迁移和每次普通前端提交无条件绑定。

## Cloudflare资源

- Worker：静态网页和 `/api/v2`。
- D1：结构化日频数据与发布快照。
- R2：原始PCF/Excel/CSV和版本备份。
- Cron Trigger：日终任务入口。
- Secret `IMPORT_TOKEN`：保护写入接口，只在Cloudflare设置。

当前 `wrangler.jsonc` 不包含D1/R2实体ID，因此仍可部署公开模拟站。创建资源后，把 `wrangler.fullstack.example.jsonc` 中的资源信息合并到正式配置。

## 安全

公开站只允许GET已发布数据。导入、重算和原始文件访问必须鉴权。未公开持仓、授权行情和公司研究数据不得进入公开API。所有写操作记录操作者、来源、文件校验和与时间。
