# 专业框架审查结论

## 美国市场对标

- ETF Database 的主动 ETF 列表采用资产规模、区间收益、成交量、费率、持仓数、前十大集中度、资金流与分项评级的可筛选横截面框架。
- Morningstar 的 ETF 页面把管理团队、风险、捕获率、组合基本面、风格箱、费用和持仓风险分栏展示，强调“持有什么、为何不同、为差异付出多少风险和成本”。
- ETF.com 使用绩效、资金流、分析、ESG和基本面分层筛选；TradingView 将主动ETF的规模、成交、NAV表现、资金流、持仓和风险放在同一横截面表中。
- ICI 的行业统计将资产规模与净发行（申购赎回）作为市场层核心指标，并强调 ETF 二级市场交易与一级市场申赎是不同层次。

因此本项目采用三级信息架构：市场总览与筛选 → 18只产品横向比较 → 单产品管理人、基本面、风格、PCF调仓、主动收益与交易质量下钻。

## 原项目问题

1. 多个源码、HTML、README 和 package.json 存在系统性乱码，部分字符串边界损坏，无法可靠构建。
2. 原 `sharpeRatio` 和 `informationRatio` 函数额外乘以 100，量纲错误；空数组和单样本也缺乏保护。
3. 产品选择器仅改变顶部产品名称，旧组件仍直接读取固定模拟数据，容易造成标题和内容不是同一产品。
4. 模拟数据未在主要指标区域持续显示数据模式与截止日期。
5. README 声称可切换 API，但没有可执行的数据适配器或 Excel 解析器。
6. 主动ETF不以复制指数为目标，不应把跟踪误差作为核心KPI；业绩基准用于评价主动收益和约束风格。

## 当前修正

主入口、数据契约和数据适配器已重建；旧源码保留但不参与构建。所有页面指标由同一选中产品驱动，并提供模拟、API、Excel三种数据模式。当前新增产品与管理人、权益风格箱、组合基本面、数据可信度、每日PCF调仓雷达、规则监测和D1后台。
